# Galaxy A21s hardware source comparison: Linux 4.19 -> 5.10

**Status:** comparison only. No A21s Linux 5.10 boot test, SUSFS integration or flash-ready boot image has been verified.

## Sources checked

- **A21s reference** — [Rakesh3464/atlas-new](https://github.com/Rakesh3464/atlas-new), branch `master`, Linux `4.19.325` (top-level `Makefile`).
- **Port target** — [Rakesh3464/android_kernel_samsung_a12s4r-5.10](https://github.com/Rakesh3464/android_kernel_samsung_a12s4r-5.10), branch `android13-5.10-lts` / development branch `a21s-susfs-port`, Linux `5.10.274` (top-level `Makefile`).

## Verified differences

| Area | A21s source / Linux 4.19 | A12s-based target / Linux 5.10 |
| --- | --- | --- |
| SoC base DTS | `arch/arm64/boot/dts/exynos/exynos3830.dts` | `arch/arm64/boot/dts/exynos/s5e3830.dts` |
| Base compatible string | `samsung,exynos850` | `samsung,exynos3830` |
| Pinctrl compatible | `samsung,exynos3830-pinctrl` | `samsung,s5e3830-pinctrl` |
| Device overlay selection in `arch/arm64/boot/dts/Makefile` | A21s: `r00`, `r01`, `r02`, `r03`, `r06` | A12s: `r00`, `r01` |
| Sample overlay available | `samsung/a21s/a21s_eur_open_w00_r00.dts` | `samsung/a12s/a12s_eur_open_w00_r00.dts` |
| A21s r00 overlay compatible | `"SAMSUNG", " A21S_EUR_OPEN", " EXYNOS850"` | No matching A21s r00 overlay at checked path |
| SoC Kconfig | Legacy Exynos-specific support present | `drivers/soc/samsung/Kconfig` contains `SOC_S5E3830` |
| Example overlay target | 4.19 r00 includes `target-path = [2f 00]` | 5.10 A12s r00 includes `target-path = "/"` |

**Important:** A21s base DTS and overlay paths are not identical to A12s. The older A21s DTS overlay includes decompiled/binary-style values such as `target-path = [2f 00]` and placeholder phandles. Merely renaming/copying files into 5.10 may cause dtc errors or runtime faults.

## Specific changes to investigate, in order

1. **Device Tree:** reconcile each A21s `r00/r01/r02/r03/r06` overlay against the 5.10 `s5e3830.dts` node names, regulator/clock/interrupt references and dtc binding expectations. Prefer validated source DTS to decompiled fragments.
2. **Board peripherals:** check A21s display panel, touch controller, camera sensors, flash/LED, battery/fuel gauge, charger, Wi-Fi/Bluetooth and modem bindings against 5.10 driver availability. Do not assume A12s hardware is identical.
3. **Config:** locate actual defconfig/fragment inputs for both trees. The 4.19 `build.config.smdk3830` names `smdk3830_defconfig`, but that file has not yet been located at the common checked paths. Validate toolchains and produced `Image`, DTB, DTBO before touching boot packaging.
4. **SUSFS:** first establish booting A21s Linux 5.10 without SUSFS. Only after that select a patchset proven compatible with the exact KernelSU/SUSFS and Linux 5.10 revisions. Perform compilation and controlled boot verification separately.
5. **Boot image:** obtain known-working device boot image metadata, ramdisk and vendor ABI information; construct a test image only after compatibility checks. Keep stock firmware and recovery access.

## Automated audit

This branch contains `a21s_porting/audit.py` and a GitHub Actions workflow at `.github/workflows/a21s-source-audit.yml` that can inventory both trees and publish an **analysis artifact**, not a flashable image. If Actions is disabled, it can be run manually on Linux after cloning both repositories with Python 3.

### Release gate

**Do not flash anything from this branch yet.** A reliable flash-ready `boot.img` needs successful kernel compilation, matching device trees and firmware, a recovery method, and real A21s boot testing.
